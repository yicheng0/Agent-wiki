公众号名称：AI信息Gap

作者名称：木易的AI频道

发布时间：2026-05-04 06:00

原文链接：[https://developers.openai.com/api/docs/guides/prompt-guidance](https://developers.openai.com/api/docs/guides/prompt-guidance)

你以前精心写的提示词，可能对 `GPT-5.5` 不管用了。

这是 OpenAI 自己说的。`GPT-5.5` 上线当天，官方就发布了一整页提示词指南。你之前写的分步流程、绝对指令、超长的角色设定，指南原文用了一个词——noise，噪音。

「Legacy prompts often over-specify the process because earlier models needed more help staying on track. With GPT-5.5, that can add noise, narrow the model's search space, or lead to overly mechanical answers.」

旧提示词之所以写那么细，是因为老模型蠢，需要手把手教。`GPT-5.5` 不需要了。你教得越多，它反而越死板。

![[4f0c7c1d020a789829048ce1ff301f9d_MD5.png]]

Django 框架联合创始人 Simon Willison 看完指南后在博客里感叹，「有意思，OpenAI 居然建议从头写，而不是信任以前调好的提示词。」

这篇文章把这份 OpenAI 官方指南里最关键的 7 个变化拆解给你。直接用 ChatGPT 或调用 API，都用得上。

  

---

### 01｜从「手把手」到「只描述结果」

以前写提示词，你可能习惯这么写。

「先检查 A，再检查 B，逐个字段对比，想清楚所有可能的异常，然后决定调用哪个工具，调完工具把全过程解释给用户。」

OpenAI 现在说，别这样了。换成这么写。

「把用户的问题彻底解决。根据现有政策和账户数据来判断，能做的事先做完再回复，最后告诉用户做了什么、还有什么没解决。缺信息就追问，只问最关键的那一个。」

区别在哪？前者规定每一步怎么走，后者只描述结果长什么样。

`GPT-5.5` 的推理能力比 `GPT-5.4` 更强，你把路线规定死了，反而可能限制它选择最优路径的能力。

![[addc71c2328435109b6f0cf056b8cff5_MD5.png]]

「描述目的地，而不是每一步怎么走」。

  

---

### 02｜「必须」和「禁止」，少用

以前为了让模型听话，提示词里塞满了绝对指令。「永远用 JSON 格式」「绝对不要超过 500 字」「必须先搜索再回答」。

`GPT-5.5` 指南里给了一条分界线。安全规则、必填字段、绝对禁止的操作，这些真正的红线才用「永远」「绝不」。但「该不该搜索、要不要追问用户」这类判断，建议用条件句。

![[9ee77b6a330cc877b62aac194f939984_MD5.png]]

举个例子。以前你可能写「回答之前必须先搜索」。现在应该改成这样。

「收到问题后先判断现有上下文能不能直接回答。能就直接回复，不用再搜索。」

为什么？`GPT-5.5` 对提示词里的绝对指令「异常敏感」。假如你写了两条互相矛盾的「必须」，它不会主动忽略其中一条，而是会耗费算力推理、试图同时满足两条限制，结果两边都做不好。

  

---

### 03｜角色定义，回来了

前段时间有一种说法，新模型不需要角色定义了，「你是一个资深 XX」这种开头是噪音。

OpenAI 的 `GPT-5.5` 指南反过来了。官方推荐的 7 段式提示词结构里，第一段就是「角色」（Role），第二段是「人设」（Personality）。

不过这里有个变化。以前的角色定义是一大段，「你是一个世界顶级的数据分析师，拥有 20 年经验，擅长...」。

现在的建议是 1、2 句话说清功能和上下文就够了。重点放在「人设」上，不是「你是谁」，而是「你怎么跟用户协作」。

![[e5aaf46e05746fde2f12a9ad062ad070_MD5.png]]

官方给了两种人设模板。

稳重型。

「你是一个靠谱的协作者，沉稳、直接。假设用户有能力且出发点是好的。能往前推进就别停下来问。」

表达型。

「采用鲜明的对话风格，聪明、好奇、适当俏皮。模糊的问题要多问，上下文够了就果断给建议。」

「人设」管的是语气、温度、风格。「协作风格」管的是行为，比如遇到模糊需求时是盲猜还是停下来问。这两件事要分开写。

  

---

### 04｜先说一句话再干活

`GPT-5.5` 在处理多步复杂任务时，可能会先「想」很久，屏幕上什么都没有。你可能以为它卡住了。

OpenAI 官方给了一个小技巧。在提示词里加一条规则，让模型在开始干活前先回复一句。

「处理多步任务时，在调用任何工具之前，先回复一条简短的用户可见更新，说明你收到了请求和第一步要做什么。控制在一两句话。」

![[38720e189ec6921102a12e2a5e1efc91_MD5.png]]

Simon Willison 说他在 OpenAI 的 Codex 里已经看到了这个模式。Codex 在处理长任务时会先说「正在分析你的代码库，先从测试文件开始」，体验立刻不一样了。

这个技巧不只是 API 能用。你给 ChatGPT 安排一个复杂任务时，也可以加一句「处理之前先告诉我你打算怎么做」，效果类似。

  

---

### 05｜必须写「停止条件」

这是很容易被遗漏的一环。

你告诉模型「搜索相关信息然后回答」，但没说什么时候该停。结果模型搜了一轮又一轮，搜到的信息越来越偏，token 烧了一堆，答案反而更分散。

指南里专门提了两种让模型停下来的方法。

第一，甚至搜索预算。

「普通问答，先搜一轮。如果首页结果已经能支撑答案，直接回答，不要再搜。只有三种情况值得搜第二轮，首页没答案、缺关键数据、或者用户要求全面覆盖。」

第二，任务循环停止。

「每完成一轮工具调用后问自己，我现在能用已有证据回答用户的核心问题了吗？能就停下来。」

这两条加上后，调用成本能降低不少，回答反而更集中，质量更高。

  

---

### 06｜官方推荐的 7 段式结构

OpenAI 给出了一个提示词骨架，适合复杂任务。每一段保持简短，只写能改变模型行为的重要信息。

```
角色（Role）        → 1-2 句话，定义模型的功能和上下文
人设（Personality）  → 语气、风格、协作方式
目标（Goal）        → 用户可见的最终产出
成功标准（Success）  → 什么条件算完成
约束（Constraints）  → 安全、商业、证据、副作用的边界
输出（Output）       → 格式、长度、语气
停止规则（Stop rules）→ 什么时候重试、回退、拒绝、追问或停止
```

  

![[9ea01a9ba652f2de268947474bb3a783_MD5.png]]

划重点，这 7 段不是每条提示词都必须写满。简单任务可能只需要「目标」+「输出」。复杂的 Agent 工作流才需要全部 7 段。

小细节，OpenAI 在开发者后台上线了一个提示词优化工具，点「优化」（Optimize），它会根据这个结构帮你重写现有的提示词。可以试试。

  

---

### 07｜格式控制和「少说两句」

`GPT-5.5` 对格式指令的响应比之前的模型灵敏得多。

API 里有一个控制详细程度的参数 `text.verbosity`，默认中等。想要更简洁的回答，设置成 `low`。

不过 API 参数只是一部分，提示词里的格式引导才是关键。

你可以在提示词里直接告诉模型「默认用自然段落回复，标题、加粗、列表、编号只在帮助读者理解的时候用」。如果你强调了「不要列表、不要标题」，`GPT-5.5` 会严格遵循指令。

改写类任务，先说「保留什么」，再说「怎么改」。

「保留原文的结构、长度和文风。在此基础上提升清晰度和流畅度。不要加新观点或新段落，除非用户要求。」

不写「保留什么」，模型默认会扩写、加内容、改结构。

  

---

一句话总结 `GPT-5.5` 的提示词哲学。

「**说清楚你要什么，别教它怎么做。**」
